# 자료구조 질답과 오답 포인트

## 1. 연속 자료구조

### Q1. 배열의 핵심 특성은?

**답변**

같은 타입의 원소가 연속된 메모리에 저장된다. 주소 계산으로 임의 접근이 O(1)이고 캐시 지역성이 좋다. 고정 배열은 크기가 정해져 있고, 중간 삽입·삭제에는 뒤 원소 이동이 필요해 O(n)이다.

**오답 포인트**

- “배열은 삽입이 불가능하다”가 아니라, 용량과 이동 비용 때문에 비효율적이거나 별도 관리가 필요하다고 설명한다.

### Q2. `vector`의 size와 capacity는 무엇인가?

**답변**

size는 현재 생성되어 있는 원소 수, capacity는 재할당 없이 담을 수 있는 저장 공간의 원소 수다. size가 capacity를 넘도록 증가하면 더 큰 버퍼를 할당하고 기존 원소를 이동 또는 복사한다.

**오답 포인트**

- capacity만 늘었다고 원소가 생성된 것은 아니다.
- 재할당 시 기존 원소를 가리키는 포인터·참조·이터레이터는 무효화된다.

### Q3. `vector`와 `list`는 언제 선택하는가?

**답변**

대부분은 캐시 친화성, 낮은 메모리 오버헤드, 임의 접근 때문에 `vector`가 우선이다. `list`는 이미 위치를 가리키는 이터레이터가 있고, 그 위치에서 노드를 O(1)에 삽입·삭제하며, 원소 주소 안정성이 필요할 때 검토한다.

**오답 포인트**

- `list`의 삽입이 항상 O(1)은 아니다. 위치를 찾는 데 O(n)이 걸릴 수 있다.
- 원소 이동이 있다는 이유만으로 실제 성능도 항상 `list`가 빠르다고 단정하지 않는다.

### Q4. 이터레이터는 무엇인가?

**답변**

컨테이너의 원소 범위를 순회하기 위한 추상화다. 역참조, 증가, 비교 등의 연산을 제공하며 컨테이너에 따라 입력, 순방향, 양방향, 임의 접근 같은 범주가 다르다. 알고리즘은 이 인터페이스를 통해 여러 컨테이너에 공통으로 동작한다.

**오답 포인트**

- 모든 이터레이터가 포인터이거나 `+ n`을 지원한다고 가정하지 않는다.

## 2. 연결 구조와 선형 ADT

### Q5. 단일 연결 리스트와 이중 연결 리스트의 차이는?

**답변**

단일 연결 리스트는 다음 노드 포인터만 가져 메모리 오버헤드가 작고 순방향 순회가 가능하다. 이중 연결 리스트는 이전·다음 포인터를 가져 양방향 순회와 현재 노드 삭제가 편하지만 포인터 저장 비용과 갱신 지점이 늘어난다.

**오답 포인트**

- 단일 연결 리스트에서 현재 노드를 삭제하려면 보통 이전 노드 정보가 필요하다.

### Q6. 스택과 큐의 차이는?

**답변**

스택은 마지막에 넣은 항목을 먼저 꺼내는 LIFO, 큐는 먼저 넣은 항목을 먼저 꺼내는 FIFO 추상 자료형이다. 스택은 호출 구조·되돌리기·DFS, 큐는 작업 대기열·BFS에 자주 쓴다.

**오답 포인트**

- 자료형의 규칙과 구현체를 구분한다. 스택과 큐는 배열이나 연결 리스트 등으로 구현할 수 있다.

### Q7. 덱(deque)은 무엇인가?

**답변**

양 끝에서 삽입과 삭제를 지원하는 자료구조다. C++ `std::deque`는 보통 여러 고정 크기 블록을 관리하므로 임의 접근은 O(1)이지만 `vector`처럼 전체가 한 덩어리의 연속 메모리라는 보장은 없다.

**오답 포인트**

- `deque`를 단순한 이중 연결 리스트로 설명하지 않는다.

## 3. 해시와 트리

### Q8. 해시 테이블의 평균·최악 복잡도는?

**답변**

적절한 해시 함수와 부하율 관리 아래 탐색·삽입·삭제의 평균은 O(1)이다. 충돌이 한곳에 몰리거나 공격적인 입력을 받으면 최악 O(n)이 될 수 있다.

**오답 포인트**

- 해시 테이블의 O(1)을 최악 복잡도처럼 말하지 않는다.

### Q9. 해시 충돌은 어떻게 해결하는가?

**답변**

- 체이닝: 버킷마다 여러 항목을 별도 구조에 저장한다.
- 개방 주소법: 같은 배열 안에서 선형·제곱 탐사나 이중 해싱으로 다른 슬롯을 찾는다.

부하율이 높아지면 재해싱해 버킷 수를 늘린다.

**오답 포인트**

- 충돌은 해시 함수가 잘못되어서만 발생하는 것이 아니다. 키 공간이 버킷 공간보다 크면 원리상 가능하다.

### Q10. `map`과 `unordered_map`의 차이는?

**답변**

`map`은 정렬된 연관 컨테이너로 탐색·삽입·삭제가 O(log n)이며 순서 순회와 범위 질의가 가능하다. `unordered_map`은 해시 기반으로 평균 O(1)이지만 키 순서를 보장하지 않는다.

**오답 포인트**

- “빠르니까 항상 `unordered_map`”은 아니다. 순서, 범위 검색, 메모리, 해시 비용, 최악 성능 요구를 함께 본다.

### Q11. 트리 순회의 종류는?

**답변**

이진 트리에서 전위는 루트-왼쪽-오른쪽, 중위는 왼쪽-루트-오른쪽, 후위는 왼쪽-오른쪽-루트 순서다. 레벨 순회는 BFS로 깊이별 방문한다. 이진 탐색 트리를 중위 순회하면 키가 정렬된 순서로 나온다.

**오답 포인트**

- 중위 순회가 정렬 결과를 주는 것은 모든 이진 트리가 아니라 이진 탐색 트리의 순서 불변식이 있을 때다.

### Q12. 이진 탐색 트리의 복잡도는?

**답변**

연산 시간은 트리 높이 h에 비례해 O(h)다. 균형 트리는 h = O(log n)이지만 편향 트리는 h = O(n)이 된다. `std::map`처럼 균형을 유지하는 트리는 로그 복잡도를 보장한다.

**오답 포인트**

- 일반 BST의 탐색을 무조건 O(log n)이라고 하지 않는다.

## 4. 힙과 선택 기준

### Q13. 힙과 우선순위 큐의 관계는?

**답변**

우선순위 큐는 가장 우선순위가 높은 원소를 제공하는 ADT이고, 이진 힙은 대표 구현이다. 최댓값 또는 최솟값 확인은 O(1), 삽입과 최상위 삭제는 O(log n)이다.

**오답 포인트**

- 힙 전체가 정렬되어 있다고 생각하지 않는다. 부모-자식 간 힙 조건만 보장한다.

### Q14. 힙을 배열로 표현할 수 있는 이유는?

**답변**

완전 이진 트리는 마지막 레벨을 제외하고 꽉 차며 왼쪽부터 채워진다. 0 기반 인덱스에서 부모는 `(i-1)/2`, 자식은 `2i+1`, `2i+2`로 계산할 수 있어 포인터 없이 저장할 수 있다.

**오답 포인트**

- 이 공식은 완전 이진 트리의 밀집된 배열 표현에 의존한다.

### Q15. 자료구조를 선택할 때 무엇을 먼저 보는가?

**답변**

필요한 연산과 빈도, 최악 지연 허용치, 원소 수, 메모리 오버헤드, 순서 보장, 주소 안정성, 캐시 지역성을 본다. 표의 복잡도만 비교하지 말고 실제 접근 패턴과 데이터 크기로 측정한다.

**오답 포인트**

- 빅오가 같다고 실제 성능이 같지 않으며, 빅오가 더 좋아도 작은 입력에서는 상수 비용이 클 수 있다.
