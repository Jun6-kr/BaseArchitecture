# C++ 질답과 오답 포인트

## 1. 빌드와 번역 단위

### Q1. C++ 프로그램의 빌드 과정은?

**답변**

1. 전처리: `#include`, 조건부 컴파일, 매크로를 처리한다.
2. 컴파일: 각 번역 단위를 검사하고 목적 코드로 변환한다.
3. 어셈블: 어셈블리 표현을 목적 파일로 만든다.
4. 링크: 목적 파일과 라이브러리의 심볼을 연결해 실행 파일을 만든다.

선언 오류나 타입 오류는 보통 컴파일 단계에서, 정의가 없거나 중복된 심볼은 링크 단계에서 발견된다.

**오답 포인트**

- `#include`가 라이브러리를 링크한다고 말하지 않는다. 헤더의 텍스트를 전처리 단계에서 포함한다.
- 컴파일 오류와 링크 오류를 모두 “문법 오류”라고 부르지 않는다.

### Q2. 선언과 정의는 어떻게 다른가?

**답변**

선언은 이름과 타입을 컴파일러에 알린다. 정의는 함수 본문이나 객체의 저장 공간처럼 실제 실체를 제공한다. 하나의 정의 규칙(ODR)에 따라 프로그램 안의 비-인라인 함수와 변수는 원칙적으로 하나의 정의만 가져야 한다.

**오답 포인트**

- 클래스 정의, 템플릿, `inline` 엔티티에는 여러 번역 단위에 동일한 정의가 나타날 수 있는 별도 규칙이 있다.

### Q3. 헤더에 함수 본문을 두면 왜 중복 정의가 생길 수 있는가?

**답변**

헤더를 여러 `.cpp`가 포함하면 함수 정의가 여러 번역 단위에 복제된다. 일반 함수라면 링크 시 중복 심볼이 될 수 있다. 짧은 함수는 `inline`, 템플릿 함수는 헤더 정의, 일반 함수는 헤더 선언과 `.cpp` 정의로 분리하는 것이 보통이다.

**오답 포인트**

- `inline`은 “반드시 인라인 치환하라”는 명령이 아니다. 핵심 언어 의미는 여러 번역 단위의 동일 정의를 허용하는 데 있다.

## 2. 객체와 값 범주

### Q4. `struct`와 `class`의 언어적 차이는?

**답변**

기본 멤버 접근 지정자와 기본 상속 접근이 다르다. `struct`는 `public`, `class`는 `private`가 기본이다. 그 밖의 생성자, 가상 함수, 템플릿 사용 능력은 같다.

**오답 포인트**

- `struct`에는 멤버 함수나 상속을 사용할 수 없다고 답하지 않는다.

### Q5. lvalue와 rvalue는 무엇인가?

**답변**

값 범주는 단순히 “주소가 있느냐”가 아니라 표현식의 정체성과 이동 가능성을 분류한다. lvalue는 지속되는 객체의 정체성을 나타내며, xvalue는 수명이 끝나 가는 객체, prvalue는 값을 계산해 임시 객체를 초기화하는 표현식이다. rvalue는 prvalue와 xvalue를 묶은 범주다.

**오답 포인트**

- “lvalue는 왼쪽에 오는 값, rvalue는 오른쪽에 오는 값”은 규칙이 아니다.
- 모든 rvalue가 주소를 가질 수 없다고 단정하지 않는다.

### Q6. 이동 생성자가 복사보다 빠른 이유는?

**답변**

동적 메모리나 OS 핸들을 소유한 객체는 자원을 새로 복제하는 대신 소유권을 넘길 수 있다. 이동 후 원본은 파괴 가능한 유효 상태여야 한다. `std::move` 자체가 이동하는 것이 아니라 lvalue를 xvalue로 캐스팅해 이동 오버로드 선택을 가능하게 한다.

**오답 포인트**

- 모든 이동이 항상 더 빠른 것은 아니다. 작은 값 타입은 복사와 비용이 같거나 컴파일러가 복사를 제거할 수 있다.
- 이동된 객체의 값이 반드시 비어 있다고 가정하지 않는다.

### Q7. Rule of Zero, Three, Five는 무엇인가?

**답변**

- Rule of Zero: 자원 소유를 표준 RAII 타입에 맡겨 특수 멤버 함수를 직접 작성하지 않는다.
- Rule of Three: 소멸자, 복사 생성자, 복사 대입 중 하나를 직접 관리하면 나머지도 검토한다.
- Rule of Five: C++11 이후 이동 생성자와 이동 대입까지 함께 검토한다.

**오답 포인트**

- 무조건 다섯 개를 구현하는 것이 목표가 아니다. 가능한 경우 Rule of Zero가 우선이다.

### Q8. 얕은 복사와 깊은 복사의 차이는?

**답변**

얕은 복사는 멤버별 값을 복사하므로 원시 소유 포인터가 같은 자원을 가리킬 수 있다. 깊은 복사는 별도 자원을 생성해 내용까지 복제한다. 가장 안전한 해법은 원시 소유 포인터 대신 `std::vector`, `std::string`, 스마트 포인터처럼 소유 정책을 표현하는 타입을 사용하는 것이다.

**오답 포인트**

- 모든 포인터 복사가 잘못은 아니다. 비소유 포인터나 공유 소유권은 의도된 얕은 복사일 수 있다.

## 3. 다형성과 객체 수명

### Q9. 오버로딩과 오버라이딩의 차이는?

**답변**

오버로딩은 같은 스코프에서 이름은 같고 매개변수 목록이 다른 함수를 컴파일 시점에 선택하는 것이다. 오버라이딩은 파생 클래스가 기반 클래스의 가상 함수를 같은 시그니처로 재정의하고 런타임 동적 디스패치를 사용하는 것이다.

**오답 포인트**

- 반환형만 다르게 해서는 오버로딩할 수 없다.
- 오버라이딩에는 `override`를 붙여 시그니처 실수를 컴파일러가 잡게 한다.

### Q10. 기반 클래스 소멸자는 언제 `virtual`이어야 하는가?

**답변**

기반 클래스 포인터나 참조를 통해 파생 객체를 다형적으로 삭제할 가능성이 있으면 가상 소멸자가 필요하다. 그렇지 않으면 `delete basePtr`의 동작은 정의되지 않는다. 다형적 기반 클래스는 보통 public virtual 소멸자를 둔다.

**오답 포인트**

- 문제를 단지 “파생 소멸자가 호출되지 않아 누수된다”로만 설명하지 않는다. 표준상 정의되지 않은 동작이다.

### Q11. 생성자와 소멸자에서 가상 함수를 호출하면?

**답변**

생성 중에는 아직 파생 부분이 완성되지 않았고, 소멸 중에는 파생 부분이 이미 파괴되었으므로 현재 생성·소멸 중인 클래스의 최종 오버라이더가 호출된다. 완성된 최파생 타입으로 디스패치되지 않는다.

**오답 포인트**

- 호출 자체가 항상 금지되는 것은 아니지만, 다형적 동작을 기대하는 설계는 피한다.

### Q12. 객체 슬라이싱이란?

**답변**

파생 객체를 기반 클래스 값으로 복사하면 기반 부분만 복사되어 파생 상태가 잘리는 현상이다. 다형성을 유지하려면 기반 클래스 포인터나 참조, 또는 적절한 다형적 값 래퍼를 사용한다.

**오답 포인트**

- 기반 클래스 참조로 받는 것은 슬라이싱이 아니다. 값 복사에서 발생한다.

## 4. 소유권과 안전성

### Q13. `unique_ptr`와 `shared_ptr`의 차이는?

**답변**

`unique_ptr`는 단독 소유권을 표현하며 복사할 수 없고 이동할 수 있다. `shared_ptr`는 제어 블록의 강한 참조 수가 0이 될 때 객체를 해제한다. 소유권이 하나면 `unique_ptr`를 기본값으로 선택하고, 실제 공유 수명이 필요할 때만 `shared_ptr`를 사용한다.

**오답 포인트**

- `shared_ptr`를 단순히 “안전한 포인터”로 남용하지 않는다. 원자적 참조 카운트 비용과 순환 참조 위험이 있다.

### Q14. `weak_ptr`는 왜 필요한가?

**답변**

객체 수명에 기여하지 않고 `shared_ptr`가 관리하는 객체를 관찰한다. 순환 참조를 끊거나 캐시처럼 대상이 살아 있을 때만 접근하는 관계에 쓴다. 사용할 때는 `lock()`으로 임시 `shared_ptr`를 얻고 성공 여부를 확인한다.

**오답 포인트**

- `weak_ptr`를 직접 역참조할 수 없다.

### Q15. `new/delete`와 `malloc/free`의 차이는?

**답변**

`new`는 타입 크기의 저장 공간을 확보하고 생성자를 호출하며, 실패 시 기본적으로 예외를 던진다. `delete`는 소멸자를 호출한 뒤 저장 공간을 해제한다. `malloc/free`는 바이트 단위 메모리만 관리하며 생성자·소멸자를 호출하지 않는다.

**오답 포인트**

- 할당과 해제 계열을 섞지 않는다. `new`에는 `delete`, `new[]`에는 `delete[]`, `malloc`에는 `free`를 대응한다.

### Q16. RAII란?

**답변**

자원의 획득을 객체 초기화에, 반환을 소멸자에 결합하는 방식이다. 스코프를 벗어날 때 예외가 발생해도 소멸자가 실행되므로 메모리, 락, 파일, 소켓을 일관되게 정리할 수 있다.

**오답 포인트**

- RAII는 메모리에만 적용되는 패턴이 아니다.

### Q17. `const` 멤버 함수의 의미는?

**답변**

숨은 `this`가 `const T*`처럼 취급되어 일반 멤버 상태를 변경할 수 없고 비-const 멤버 함수를 호출할 수 없다. 논리적으로 값이 변하지 않는 관찰 연산을 표현한다. 캐시나 동기화 객체처럼 논리적 상태가 아닌 멤버는 신중하게 `mutable`로 둘 수 있다.

**오답 포인트**

- 포인터 멤버가 가리키는 외부 객체까지 자동으로 const가 되는 것은 아니다.

### Q18. 복사 생성자를 막는 현대적인 방법은?

**답변**

복사 생성자와 복사 대입을 `= delete`로 명시한다.

```cpp
class Socket {
public:
    Socket(const Socket&) = delete;
    Socket& operator=(const Socket&) = delete;
};
```

**오답 포인트**

- C++11 이후에는 private 선언만 하고 정의하지 않는 옛 기법보다 `= delete`가 의도를 명확히 하고 진단도 좋다.
