# CS·게임 개발 면접 질답과 오답 포인트

## 1. 운영체제와 동시성

### Q1. 가상 메모리는 무엇인가?

**답변**

프로세스마다 독립적인 가상 주소 공간을 제공하고 페이지 테이블을 통해 물리 메모리에 매핑한다. 보호, 공유, 주소 재배치, 필요 시 디스크 백업 저장소 활용을 가능하게 한다.

**오답 포인트**

- 단순히 “RAM보다 큰 메모리를 쓰는 기술”로만 설명하지 않는다.

### Q2. 페이지 폴트란?

**답변**

가상 주소 변환 중 현재 유효한 물리 매핑이 없어 CPU가 OS로 제어를 넘기는 예외다. 아직 적재되지 않은 정상 페이지라면 OS가 매핑 후 재실행할 수 있고, 잘못된 접근이면 프로세스 오류가 된다.

**오답 포인트**

- 모든 페이지 폴트가 디스크 I/O를 발생시키는 것은 아니다.

### Q3. 컨텍스트 스위칭 비용은 어디서 생기는가?

**답변**

레지스터·스택 포인터·스케줄링 상태를 저장·복원하고, 캐시와 TLB의 유효성이 떨어지며 파이프라인이 흐트러지는 데서 비용이 생긴다.

**오답 포인트**

- 단순한 함수 호출과 같은 비용으로 보지 않는다.

### Q4. 데드락의 네 조건은?

**답변**

상호 배제, 점유 대기, 비선점, 순환 대기다. 네 조건이 동시에 성립해야 한다. 락 순서를 통일하거나 한 번에 획득하고, 범위를 줄이며, 필요하면 `std::scoped_lock` 같은 도구를 사용한다.

**오답 포인트**

- 타임아웃은 감지·회복 전략일 수 있지만 공유 상태의 일관성을 자동 보장하지 않는다.

### Q5. 뮤텍스, 세마포어, 스핀락의 차이는?

**답변**

뮤텍스는 보통 소유자가 잠그고 해제하는 상호 배제 도구다. 세마포어는 카운트로 제한된 자원 수나 신호를 표현한다. 스핀락은 기다리는 동안 CPU에서 반복 확인하므로 대기가 매우 짧고 스레드가 선점되지 않는 조건에서만 유리하다.

**오답 포인트**

- 스핀락을 오래 보유하거나 단일 코어 환경에서 무조건 빠르다고 하지 않는다.

## 2. 네트워크

### Q6. TCP와 UDP의 차이는?

**답변**

TCP는 연결 지향 바이트 스트림으로 순서, 재전송, 흐름·혼잡 제어를 제공한다. UDP는 데이터그램 단위이며 전달·순서·중복 방지를 보장하지 않는 대신 헤더와 상태가 단순하고 애플리케이션이 필요한 신뢰성만 설계할 수 있다.

**오답 포인트**

- UDP는 “항상 빠르다”, TCP는 “패킷 경계를 보존한다”고 답하지 않는다.

### Q7. TCP 3-way handshake는 왜 세 단계인가?

**답변**

클라이언트와 서버가 서로의 초기 시퀀스 번호와 양방향 송수신 가능성을 확인한다. SYN, SYN-ACK, ACK 순으로 연결 상태를 동기화한다.

**오답 포인트**

- handshake가 애플리케이션 데이터의 종단 간 처리 완료까지 보장하는 것은 아니다.

### Q8. Nagle 알고리즘은 무엇인가?

**답변**

작은 TCP 세그먼트가 과도하게 발생하지 않도록 확인되지 않은 데이터가 있을 때 작은 전송을 모으는 방식이다. 대역 효율을 높이지만 지연에 민감한 상호작용에서는 지연 ACK와 결합해 체감 지연을 만들 수 있다.

**오답 포인트**

- `TCP_NODELAY`를 무조건 켜거나 끄지 말고 메시지 패턴을 측정한다.

### Q9. MTU와 단편화는?

**답변**

MTU는 한 링크에서 추가 단편화 없이 보낼 수 있는 IP 패킷의 최대 크기다. 경로 MTU보다 큰 패킷은 IPv4에서 단편화되거나, DF 설정 시 폐기되고 알림을 받을 수 있다. UDP 게임 프로토콜은 보통 단편화를 피하도록 페이로드를 작게 설계한다.

**오답 포인트**

- 이더넷 MTU 1500을 모든 경로에서 절대값으로 가정하지 않는다.

### Q10. `select`, `poll`, `epoll`의 차이는?

**답변**

`select`는 비트셋과 FD 수 제한, 매 호출 전체 집합 복사·검사가 있다. `poll`은 배열로 제한을 완화하지만 여전히 전체를 검사한다. Linux `epoll`은 관심 목록을 커널에 유지하고 준비 이벤트를 반환해 많은 연결에서 유리하다.

**오답 포인트**

- 연결 수가 적을 때도 `epoll`이 항상 더 빠르다고 단정하지 않는다.

## 3. 그래픽스와 수학

### Q11. 렌더링 파이프라인의 큰 흐름은?

**답변**

정점 입력 → 정점 처리 → 선택적 테셀레이션·지오메트리 처리 → 래스터화 → 픽셀/프래그먼트 처리 → 깊이·스텐실·블렌딩을 거쳐 출력 병합으로 이어진다. 세부 단계는 API와 파이프라인 구성에 따라 달라진다.

**오답 포인트**

- 모든 단계가 항상 활성화된다고 말하지 않는다.

### Q12. 깊이 버퍼와 스텐실 버퍼의 차이는?

**답변**

깊이 버퍼는 픽셀별 깊이를 저장해 가시성 테스트에 사용한다. 스텐실 버퍼는 작은 정수 마스크로 특정 영역의 렌더링 허용·차단, 윤곽선, 포털 등에 사용한다.

**오답 포인트**

- 둘 다 화면 크기 버퍼일 수 있지만 저장 의미와 테스트 목적이 다르다.

### Q13. Forward와 Deferred Rendering의 차이는?

**답변**

Forward는 물체를 그릴 때 조명을 함께 계산해 투명 처리와 MSAA가 자연스럽지만 많은 광원에서 중복 계산이 늘 수 있다. Deferred는 먼저 G-buffer에 재질 정보를 저장한 뒤 화면 공간에서 조명을 계산해 많은 동적 광원에 유리하지만 메모리 대역폭, 투명체, MSAA 처리 비용이 있다.

**오답 포인트**

- Deferred가 모든 장면에서 더 빠르다고 하지 않는다. 광원 수, 오버드로, 플랫폼 대역폭을 본다.

### Q14. 내적과 외적은 게임에서 어떻게 쓰는가?

**답변**

내적은 두 벡터의 방향 유사도와 투영을 구해 시야 판정, 조명 계산에 쓴다. 외적은 두 벡터에 수직인 벡터와 방향성을 구해 법선, 좌우 판정, 좌표축 생성에 쓴다.

**오답 포인트**

- 내적으로 각도를 구할 때는 벡터 정규화 또는 길이 보정이 필요하며 `acos` 입력을 [-1, 1]로 제한한다.

### Q15. 쿼터니언의 장점은?

**답변**

3차원 회전을 간결하게 합성하고 정규화된 쿼터니언 사이를 보간할 수 있으며, 오일러 각의 표현 특이점인 짐벌락을 피한다.

**오답 포인트**

- 쿼터니언을 쓰면 수치 오차가 사라지는 것은 아니다. 누적 회전 후 정규화가 필요할 수 있다.

### Q16. AABB와 OBB의 차이는?

**답변**

AABB는 월드 축에 정렬되어 교차 검사가 빠르지만 회전 물체를 느슨하게 감쌀 수 있다. OBB는 객체 방향을 따라 더 타이트하지만 축과 반축 정보를 관리하고 분리축 검사 비용이 더 든다.

**오답 포인트**

- 충돌 시스템은 보통 값싼 broad phase와 정밀 narrow phase를 조합한다.

## 4. Unreal과 게임 구조

### Q17. `UObject`와 `AActor`의 관계는?

**답변**

`UObject`는 Unreal의 리플렉션, 직렬화, 가비지 컬렉션 기반 객체다. `AActor`는 `UObject`를 상속하며 월드에 배치·스폰되고 Transform, 네트워크 복제, 라이프사이클을 가진다.

**오답 포인트**

- 모든 `UObject`가 월드에 존재하거나 Transform을 갖는 것은 아니다.

### Q18. Actor와 Component의 관계는?

**답변**

Actor는 월드의 개체와 수명 경계를 나타내고, Component는 렌더링·충돌·이동 같은 재사용 기능을 Actor에 조합한다. `USceneComponent`는 Transform 계층을 가질 수 있다.

**오답 포인트**

- Component를 독립 Actor처럼 임의로 스폰한다고 설명하지 않는다.

### Q19. Unreal GC의 Root Set은?

**답변**

GC가 도달 가능성을 추적하기 시작하는 루트 객체 집합이다. 루트에서 반사 시스템이 인식하는 강한 참조를 따라 도달 가능한 `UObject`를 보존한다.

**오답 포인트**

- 원시 C++ 포인터만 보관하면 GC가 항상 참조를 안다고 가정하지 않는다. 엔진 버전과 용도에 맞는 `UPROPERTY`, `TObjectPtr`, 약한 포인터 등을 사용한다.

### Q20. Replication과 RPC의 차이는?

**답변**

Replication은 서버 권위 상태를 연결별로 동기화하는 메커니즘이고, RPC는 특정 시점의 함수 호출 의도를 원격에 전달한다. 지속 상태는 복제 변수, 순간 사건은 RPC가 자연스럽지만 신뢰성·빈도·소유권 규칙을 함께 설계한다.

**오답 포인트**

- Reliable RPC를 매 프레임 보내면 큐 적체로 오히려 연결 품질이 악화될 수 있다.

### Q21. CPU 바운드와 GPU 바운드는 어떻게 구분하는가?

**답변**

프로파일러로 CPU 프레임 시간과 GPU 프레임 시간을 측정하고, 해상도나 렌더 품질을 낮췄을 때 프레임 시간이 크게 줄면 GPU 병목 가능성이 높다. CPU에서는 게임·렌더 스레드 구간과 대기 시간을 따로 본다.

**오답 포인트**

- 사용률 숫자 하나로 결론 내리지 않는다. 동기화 때문에 한쪽이 다른 쪽을 기다릴 수 있다.

### Q22. 최적화의 올바른 순서는?

**답변**

목표 프레임 예산 정의 → 재현 가능한 장면 측정 → 가장 큰 병목 식별 → 한 번에 한 변경 → 전후 비교 → 회귀 방지 순서다.

**오답 포인트**

- 감으로 자료구조나 패턴을 교체하지 않는다. 성능과 코드 복잡도의 비용을 함께 기록한다.
