## 시작 복습 — 스마트 포인터

단독·공동 소유와 이동·파괴 기준을 기억했다. `weak_ptr::lock()`은 답안을 참고했으므로 자력 인출 실패로 기록한다. `weak_ptr`는 객체를 비소유로 관찰하며, `lock()`에 성공하면 일시적으로 수명을 유지하는 `shared_ptr`를 얻는다. 대상이 이미 파괴되었다면 빈 `shared_ptr`가 반환된다.

## 질답 기록

### Q1~Q5. 템플릿

1. **함수 오버로드를 템플릿으로 바꾸기 (🟢).** `template<typename T> T Max(T a, T b) { return a > b ? a : b; }`를 정확히 작성했다.
2. **`Max(3, 4.5)` 타입 추론 (🟢).** 두 인자에서 동일한 `T`가 추론되어야 한다는 점을 설명하고 명시적 타입 지정을 제안했다. `4.5`는 `double`이며, `Max<double>(3, 4.5)`에서는 첫 인자가 변환된다. `Max<int>`를 쓰면 소수부가 잘린다.
3. **사용자 정의 타입 (🟢).** `Player`에서 `>`를 사용할 수 없으면 `Max<Player>` 본문을 인스턴스화할 수 없다고 답했다. 예를 들어 `level`을 비교하는 `operator>`를 제공할 수 있다.
4. **정의의 가시성 (🟢).** 선언만 헤더에 두고 정의를 다른 번역 단위에 숨기면, 필요한 `Max<int>` 정의가 제공되지 않아 보통 링크 오류가 난다고 판단했다. 호출 측에서 정의를 볼 수 있게 하거나, 정의가 있는 `.cpp`에 `template int Max<int>(int, int);`처럼 명시적 인스턴스화 정의를 제공한다.
5. **클래스 템플릿의 정적 멤버 (🟢).** `Counter<int>` 객체 두 개와 `Counter<double>` 객체 한 개를 생성하면, 각 특수화가 별개의 정적 멤버를 갖는다. `count`는 총 두 개이며 각각 2, 1이다.

### Q6~Q10. 이터레이터 범위와 유효성

6. **`begin()`과 `end()` (🟢).** `{10, 20, 30}`에서 `begin()`을 한 번 증가시키고 역참조하면 20이다. `end()`는 마지막 원소 바로 다음 위치를 나타내며 역참조할 수 없다. 빈 범위에서는 `begin() == end()`다.
7. **`vector`와 `list`의 이동 연산 (🟡 → 🟢).** 처음에는 둘 다 `+=`가 가능하다고 답했다. `vector`는 임의 접근을 지원하고 `list`는 양방향 이동을 지원한다. 확인 질문에서는 `std::advance(it, n)`의 비용이 각각 O(1), O(n)임을 정확히 설명했다. 여기서 `n`은 유효한 양의 이동 거리다.
8. **`push_back()`과 무효화 (🟢).** 용량이 가득 차 재할당하면 기존 위치를 가리키던 이터레이터를 사용할 수 없다고 설명했다. 재할당이 없으면 기존 원소 이터레이터는 유지되지만 이전 `end()`는 무효화된다.
9. **순회 중 `erase()` (🟡).** 삭제 뒤 위치를 갱신해야 한다고 판단했지만 기존 이터레이터에 `++`를 제안했다. `vector::erase`는 삭제 위치부터 기존 `end()`까지 이터레이터를 무효화하며, 다음 위치의 유효한 이터레이터를 반환한다.
10. **`std::sort`와 `list::sort` (🟡).** 컴파일 여부는 맞혔고 비교 람다로 해결할 수 있을지 추측했다. 비교자는 정렬 기준을 정한다. `std::sort`에는 임의 접근 이터레이터가 필요하므로 `list`에서는 `b.sort()` 또는 `b.sort(comparator)`를 사용한다.

```cpp
for (auto it = values.begin(); it != values.end();)
{
    if (*it % 2 == 0)
        it = values.erase(it);
    else
        ++it;
}
```

### Q11~Q14. 제네릭 순회와 const

11. **`PrintRange` 구현 (🟡).** 범위 비교와 출력은 제대로 작성했고 반복 변수 증가가 빠졌다. 아래와 같이 `++iter`를 넣는다.
12. **템플릿 본문의 요구사항 (🟡).** 출력 스트림의 `<<`는 정확히 찾았다. 이 구현은 이터레이터 복사, `!=` 비교, `++` 전진, `*` 역참조와 역참조 결과의 스트림 삽입이 가능해야 한다. 일반적인 순회에는 감산이나 순서 비교가 필요 없다.
13. **상수 컨테이너 (🟢).** `const std::vector<int>`의 `begin()`은 `const_iterator`를 반환하므로 `*it = 100`은 컴파일 오류다.
14. **`const auto`와 `cbegin()` (🟡).** 일반 이터레이터 자체에 붙는 `const`와 원소 접근에 적용되는 `const_iterator`를 바꿔 생각했다. 비상수 `vector`에서 `const auto it = values.begin()`은 `*it = 100`만 가능하고, `auto cit = values.cbegin()`은 `++cit`만 가능하다.

```cpp
template<typename Iterator>
void PrintRange(Iterator first, Iterator last)
{
    for (auto iter = first; iter != last; ++iter)
        std::cout << *iter << '\n';
}
```

## 면접 답변

처음에는 템플릿을 STL 기능이라고 설명했다. 교정 후에는 정의, 인스턴스화, 헤더 배치, 명시적 인스턴스화를 자신의 말로 다시 설명했다.

> C++ 템플릿은 타입이나 값을 매개변수화해 여러 입력에 대응하는 함수나 클래스를 작성하는 언어 기능입니다. 구체적인 인자로 필요한 함수나 클래스를 만드는 과정을 인스턴스화라고 합니다. 호출 측에서 암시적으로 인스턴스화하려면 정의가 보여야 하므로 일반적으로 헤더에 정의를 둡니다. 정의를 `.cpp`에 두는 경우에는 공개할 타입에 대해 명시적 인스턴스화 정의를 제공할 수 있습니다. 이터레이터는 컨테이너의 원소 범위를 공통 방식으로 순회하고 알고리즘에 전달하는 수단입니다. 범주별 지원 연산과 복잡도, 컨테이너 변경으로 인한 무효화를 확인해야 합니다.
