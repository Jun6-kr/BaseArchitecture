## 질답 기록

### Q1. C++ 소스가 실행 파일이 되는 과정은?

**학습자 답변 요약**

전처리에서 매크로와 헤더를 본문에 반영하고, 컴파일과 어셈블을 거친 뒤 링크 단계에서 라이브러리와 함수 선언·정의를 연결한다고 답했다.

**평가: 🟡**

전체 단계 순서는 맞았지만 컴파일과 어셈블의 중간 산출물을 반대로 설명했다. 링커의 역할도 문법 검사보다 심볼 해결과 재배치로 표현해야 한다.

**교정된 답변**

1. 전처리: 매크로와 조건부 컴파일을 처리하고 헤더 내용을 포함한다.
2. 컴파일: 전처리된 C++를 분석해 어셈블리 또는 이에 준하는 중간 표현으로 변환한다.
3. 어셈블: 기계어와 심볼 정보가 담긴 목적 파일을 만든다.
4. 링크: 목적 파일과 라이브러리의 심볼 참조를 정의에 연결하고 실행 파일 또는 라이브러리를 만든다.

### Q2. 선언되지 않은 함수 호출과 정의 없는 함수 호출은 어느 단계의 오류인가?

**학습자 답변 요약**

선언되지 않은 호출은 컴파일 오류, 선언은 있지만 정의가 없는 호출은 링크 오류라고 답했다.

**평가: 🟢**

단계 구분이 정확했다. 컴파일러는 현재 번역 단위에서 선언과 타입을 검사하고, 링커는 목적 파일 전체에서 필요한 정의를 찾는다.

### Q3. 선언만 있고 호출하지 않은 함수는 왜 정의가 없어도 되는가?

**학습자 답변**

“호출되지 않아서.”

**평가: 🟢**

실제로 사용되지 않아 목적 파일에 해결할 심볼 참조가 생기지 않으므로 정의가 필요하지 않다.

### Q4. 번역 단위란 무엇인가?

**학습자 답변 변화**

처음에는 `main()`이 진입점이므로 먼저 컴파일되는지 추측했다. 설명 후에는 각 `.cpp`가 포함한 헤더 내용을 전처리로 가져오며 서로 독립적으로 컴파일된다고 정확히 정리했다. 또한 헤더가 별도 번역 단위를 갖는 것이 아니라 각 소스의 번역 단위에 포함된다는 점을 스스로 추론했다.

**평가: 🟡 → 🟢**

**교정된 정의**

번역 단위는 하나의 소스 파일에 전처리를 적용한 결과이며, 컴파일러가 독립적으로 입력받아 컴파일하는 단위다. `Main.cpp`와 `Player.cpp`는 각각 별도의 번역 단위가 되고, 빌드 시스템은 이를 독립적 또는 병렬로 컴파일할 수 있다. `main()`은 런타임 진입점이지 컴파일 순서를 결정하지 않는다.

### Q5. 같은 헤더를 여러 경로로 포함할 때 중복을 어떻게 막는가?

**학습자 답변 요약**

번역 단위마다 한 번만 포함해야 한다는 목적은 이해했지만 방법은 알지 못했다.

**평가: 🟡**

`#pragma once` 또는 include guard를 사용한다. 이 장치는 프로젝트 전체가 아니라 **각 번역 단위 안에서** 같은 헤더가 반복 처리되는 것을 막는다.

```cpp
#ifndef GAME_H
#define GAME_H

struct Game
{
};

#endif
```

### Q6. 헤더에 일반 함수 정의를 두고 여러 `.cpp`가 포함하면 왜 문제가 되는가?

**학습자 답변 요약**

전처리 결과 각 번역 단위에 같은 함수 정의가 생기고, 링크 단계에서 어느 정의인지 구분할 수 없어 문제가 된다고 답했다.

**평가: 🟢**

원인을 정확히 찾았다. 더 엄밀하게는 링커가 단순히 “헷갈리는” 것이 아니라, 외부 연결을 가진 동일 심볼의 정의가 여러 개 생겨 ODR을 위반한다.

### Q7. 헤더와 소스에 함수 선언·정의를 어떻게 배치하는가?

**학습자 답변 요약**

헤더에 `void StartGame();`을 선언하고 `Game.cpp`에 정의하면 된다고 답했다.

**평가: 🟢**

정확하다. `Game.cpp`도 자기 헤더를 포함해 선언과 정의 사이의 불일치를 가능한 한 빨리 발견하도록 한다.

### Q8. 정의가 있는 `.cpp`를 빌드에서 제외하면 어떻게 되는가?

**학습자 답변 요약**

헤더 선언이 있으므로 컴파일은 통과하지만, 링크 단계에서 정의와 연결할 수 없어 실패한다고 답했다.

**평가: 🟢**

컴파일러와 링커의 책임을 정확히 구분했다.

### Q9. 헤더는 `StartGame(int)`, 소스는 `StartGame(float)`를 정의하면?

**학습자 답변 요약**

처음에는 `Game.cpp`의 컴파일 오류라고 답했다.

**평가: 🔴**

두 함수는 서로 다른 오버로드이므로 각각의 번역 단위는 컴파일될 수 있다. 호출부가 요구하는 `StartGame(int)` 정의가 어디에도 없으므로 최종적으로 링크 오류가 발생한다.

### Q10. 종합 설명

**학습자 답변 요약**

- 번역 단위를 목적 파일을 만드는 가장 작은 파일 단위로 설명했다.
- 헤더 정의가 각 번역 단위에 복제되므로 선언과 정의를 분리한다고 설명했다.
- 컴파일러가 함수 선언과 정의의 일치를 검사하고 링커가 선언과 정의를 연결한다고 설명했다.

**평가: 🟡**

전체 흐름은 이해했다. 다만 번역 단위는 파일 크기 개념이 아니라 전처리된 소스라는 점, 컴파일러는 서로 다른 번역 단위의 선언·정의를 직접 대조하지 않는다는 점을 보완해야 한다.

## 오늘 잘한 점

- 컴파일 오류와 링크 오류를 대부분 정확히 분류했다.
- 헤더가 별도로 컴파일되는 것이 아니라 각 `.cpp`에 포함된다는 사실을 설명 후 스스로 추론했다.
- 헤더의 일반 함수 정의가 여러 번역 단위에 복제되는 문제를 정확히 찾았다.
- 정의 파일이 빌드에서 빠진 상황을 링크 오류로 정확히 진단했다.

## 오답 및 보완 항목

### 1. 컴파일과 어셈블의 산출물

- 오답: 컴파일이 목적 파일을 만들고 어셈블이 어셈블리 파일을 만든다.
- 교정: 개념적 순서는 C++ → 컴파일 → 어셈블리 → 어셈블 → 목적 파일이다. 실제 도구는 두 단계를 한 번에 수행할 수 있다.

### 2. 번역 단위의 정의

- 오답 경향: 목적 파일을 만들 수 있는 가장 작은 파일 단위로만 기억함.
- 교정: **하나의 소스 파일을 전처리한 결과이며 독립적인 컴파일 입력**이다.

### 3. 컴파일러의 검사 범위

- 오답 경향: 컴파일러가 프로젝트 전체의 선언과 정의를 비교한다고 이해함.
- 교정: 컴파일러는 현재 번역 단위 안의 문법·타입·선언 사용을 검사하고, 링커가 목적 파일 사이의 심볼을 해결한다.

### 4. 다른 매개변수 타입은 다른 심볼

- 오답: `StartGame(int)` 선언과 `StartGame(float)` 정의가 컴파일 단계에서 불일치로 검출된다.
- 교정: 둘은 합법적인 별도 오버로드다. `StartGame(int)`의 정의 누락이 링크 단계에서 검출된다.

## 최종 30초 답변

> 각 `.cpp`는 포함한 헤더와 매크로를 전처리한 뒤 하나의 번역 단위로 독립적으로 컴파일됩니다. 컴파일과 어셈블을 거쳐 목적 파일이 만들어지고, 링커가 여러 목적 파일과 라이브러리의 심볼 참조를 정의에 연결해 실행 파일을 만듭니다. 컴파일 오류는 현재 번역 단위의 문법·타입·선언 사용 문제이고, 링크 오류는 필요한 정의가 없거나 같은 외부 정의가 중복되는 문제입니다.
