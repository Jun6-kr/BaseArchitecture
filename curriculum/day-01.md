# Day 01 - C++ 빌드 과정과 번역 단위

## 오늘의 목표

학습 후 다음을 할 수 있어야 합니다.

- C++ 소스가 실행 파일이 되는 과정을 순서대로 설명한다.
- 컴파일 오류와 링크 오류를 구분한다.
- 헤더, 소스 파일, 목적 파일의 역할을 설명한다.
- 번역 단위가 무엇인지 자신의 말로 정의한다.

예상 시간: **70분**

## 1. 사전 인출 - 10분

자료를 보지 않고 먼저 답해 봅니다.

1. `#include`는 어느 단계에서 처리되는가?
2. 다른 `.cpp`에 있는 함수의 정의를 찾지 못했다면 어떤 오류인가?
3. 헤더 파일과 라이브러리는 같은 것인가?
4. `.cpp` 파일 두 개는 한 번에 하나의 단위로 컴파일되는가?

답을 메모한 뒤 아래 내용과 비교합니다.

## 2. 핵심 개념 - 20분

### 전체 흐름

```text
소스·헤더
   ↓ 전처리
번역 단위
   ↓ 컴파일·어셈블
목적 파일(.o / .obj)
   ↓ 링크 + 라이브러리
실행 파일
```

### 전처리

`#include`, `#define`, `#if` 같은 전처리 지시문을 처리합니다. `#include`는 헤더 파일의 내용을 현재 파일에 포함시키는 방식으로 동작합니다.

### 컴파일과 어셈블

전처리된 각 번역 단위를 검사하고 목적 코드로 변환합니다. 타입 불일치, 선언되지 않은 이름, 문법 오류는 이 과정에서 주로 발견됩니다.

### 링크

여러 목적 파일과 라이브러리의 심볼을 연결합니다. 선언은 보았지만 정의를 찾지 못했거나 같은 외부 심볼이 여러 번 정의되었다면 링크 오류가 발생할 수 있습니다.

### 번역 단위

하나의 소스 파일에 전처리 결과로 포함된 헤더 내용까지 합친 컴파일 입력 단위입니다. 여러 `.cpp`는 보통 각각 별도 번역 단위로 컴파일된 후 링크 단계에서 결합됩니다.

## 3. 코드 추적 - 15분

다음 세 파일을 가정합니다.

```cpp
// Calculator.h
#pragma once

int Add(int left, int right);
```

```cpp
// Calculator.cpp
#include "Calculator.h"

int Add(int left, int right)
{
    return left + right;
}
```

```cpp
// Main.cpp
#include <iostream>
#include "Calculator.h"

int main()
{
    std::cout << Add(2, 3) << '\n';
}
```

확인할 것:

1. `Main.cpp`는 `Add`의 선언을 헤더에서 본다.
2. `Calculator.cpp`가 `Add`의 정의를 제공한다.
3. 두 `.cpp`가 각각 목적 파일이 된다.
4. 링커가 `Main`의 호출과 `Calculator`의 정의를 연결한다.

## 4. 오류 분류 실습 - 10분

각 상황을 컴파일 오류 또는 링크 오류로 분류합니다.

| 상황 | 정답 | 이유 |
| --- | --- | --- |
| 세미콜론을 빠뜨림 | 컴파일 오류 | 문법을 해석할 수 없음 |
| 선언되지 않은 함수를 호출함 | 컴파일 오류 | 현재 번역 단위가 이름을 모름 |
| 함수 선언은 있지만 정의 파일을 빌드에서 제외함 | 링크 오류 | 호출 심볼의 정의를 찾지 못함 |
| 같은 비-인라인 함수를 두 `.cpp`에서 정의함 | 링크 오류 | 외부 심볼이 중복됨 |
| 인자 타입이 선언과 맞지 않음 | 컴파일 오류 | 올바른 호출을 만들 수 없음 |

## 5. 자주 틀리는 포인트 - 5분

- `#include`는 라이브러리를 링크하는 명령이 아니다.
- 헤더에는 보통 선언과 타입 정의가 있으며, 실행 코드는 목적 파일·라이브러리에서 링크된다.
- 모든 빌드 실패를 “컴파일 에러”라고 부르면 원인 탐색 범위가 넓어진다.
- `inline`은 컴파일러가 반드시 함수 호출을 치환한다는 뜻이 아니다.

## 6. 마무리 테스트 - 10분

3. 번역 단위는 무엇입니까?
4. 헤더에 일반 함수 정의를 작성했을 때 왜 문제가 될 수 있습니까?

### 모범 답변의 핵심어

- 전처리 → 컴파일·어셈블 → 링크
- 선언은 보았지만 정의가 없거나 빌드에 포함되지 않음
- 소스 파일과 포함된 헤더를 전처리한 독립 컴파일 단위
- 여러 번역 단위에 같은 외부 정의가 생겨 ODR 또는 중복 심볼 문제
