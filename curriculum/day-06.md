## 질답 기록

### Q1. 헤더에 정의한 전역 변수는 왜 중복 정의되는가?

```cpp
// Config.h
#pragma once
int maxPlayerCount = 4;
```

**학습자 답변**

링크 단계에서 중복 정의 문제가 발생하며, 번역 단위마다 `maxPlayerCount`가 별도로 정의되기 때문이라고 답했다.

**평가: 🟢**

`#pragma once`는 하나의 번역 단위 안에서 같은 헤더가 반복 포함되는 것만 막는다. 서로 다른 번역 단위가 헤더를 한 번씩 포함하는 것은 막지 않는다. C++17 이상에서는 헤더에 `inline int maxPlayerCount = 4;`를 사용할 수 있고, 전통적인 방식은 헤더에 `extern` 선언을 두고 한 `.cpp`에 유일한 정의를 두는 것이다.

### Q2. 선언과 정의를 구분하면?

```cpp
extern int score;       // 선언
int score;              // 정의
void StartGame();       // 선언
void StartGame() {}     // 정의
class Player;           // 선언
class Player {};        // 정의
```

**학습자 답변**

정의에 해당하는 `2`, `4`, `6`을 모두 정확히 골랐다.

**평가: 🟢**

정의는 선언이기도 하지만 모든 선언이 정의인 것은 아니다.

### Q3. 함수 선언과 다른 시그니처를 정의하면?

```cpp
void StartGame(int stage);   // Game.h
void StartGame(float stage)  // Game.cpp의 정의
```

**학습자 답변**

컴파일은 성공하지만, 호출된 `StartGame(int)`의 정의가 없기 때문에 링크가 실패한다고 답했다.

**평가: 🟢**

두 함수는 서로 다른 오버로드다. 각 번역 단위의 타입 검사는 통과하지만 `StartGame(int)`의 정의를 링크할 수 없다.

### Q4. 전방 선언만으로 포인터는 선언하면서 멤버 함수는 호출할 수 없는 이유는?

**학습자 답변**

포인터 선언에는 `Player`의 크기와 내부 정보가 필요하지 않지만, 멤버 함수를 사용하려면 클래스 정의가 필요하므로 `Enemy.cpp`에서 `Player.h`를 포함해야 한다고 답했다.

**평가: 🟢**

전방 선언으로 얻는 불완전 타입은 포인터와 참조 선언에 사용할 수 있다. 멤버 접근에는 완전한 클래스 정의가 필요하다.

### Q5. 멤버 생성 중 예외가 발생하면 어떤 소멸자가 호출되는가?

```text
Renderer+ -> Audio+ -> Renderer- -> Caught
```

**학습자 답변**

멤버는 선언 순서로 생성되며, `Audio`는 생성이 완료되지 않았으므로 소멸되지 않고 이미 완성된 `Renderer`만 소멸한다고 정확히 설명했다.

**평가: 🟢**

완성되지 않은 `Game`과 `Audio`의 소멸자는 호출되지 않는다. 생성이 끝난 하위 객체만 역순으로 소멸한다.

### Q6. 조기 반환이 있는 잠금 코드를 RAII로 고치면?

**학습자 답변**

조기 반환 시 `unlock()`이 호출되지 않는 문제와 RAII 잠금 객체의 동작은 설명했지만 `std::lock_guard`의 이름을 기억하지 못했다.

**평가: 🟡**

```cpp
void Update(bool paused)
{
    std::lock_guard<std::mutex> lock(mutex);

    if (paused)
        return;
}
```

`lock` 객체의 생성자가 잠그고 소멸자가 해제하므로 정상 반환, 조기 반환, 예외 모두에서 잠금이 해제된다.

### Q7. 원시 포인터 멤버의 기본 복사가 위험한 이유는?

**학습자 답변**

복사 생성자가 포인터 주소만 얕게 복사해 두 객체가 같은 배열을 가리키며, 역순 소멸 과정에서 댕글링 포인터와 이중 해제가 발생한다고 답했다.

**평가: 🟢**

### Q8. 깊은 복사 생성자를 구현하면?

**학습자 답변**

새 배열을 할당하고 `memcpy`로 원소를 복사하는 방향은 맞았으나, 매개변수의 `const`, 배열 할당 문법의 타입, `memcpy`의 바이트 수를 빠뜨렸다.

**평가: 🟡**

```cpp
Buffer(const Buffer& other)
    : data(new int[other.size]),
      size(other.size)
{
    std::memcpy(data, other.data, sizeof(int) * size);
}
```

같은 타입을 값으로 받으려면 매개변수를 만드는 데 다시 복사가 필요하므로 유효한 복사 생성자가 될 수 없다.

### Q9. 이동 생성자를 구현하면?

**학습자 답변**

원본 포인터와 크기를 넘겨받고 원본을 `nullptr`, `0`으로 만드는 코드를 정확히 작성했다. 원시 포인터에도 `std::move`를 사용했지만 필요하지 않다는 점을 교정했다.

**평가: 🟢**

```cpp
Buffer(Buffer&& other) noexcept
    : data(other.data), size(other.size)
{
    other.data = nullptr;
    other.size = 0;
}
```

### Q10. `std::move`가 실제로 수행하는 일은?

**학습자 답변**

우측값으로 변환하는 역할이며, 실제 자원 이전은 이동 생성자 내부에서 수행해야 한다고 답했다.

**평가: 🟢**

더 정확히는 표현식을 xvalue로 만드는 캐스트다. 원시 포인터를 `std::move`해도 원본이 자동으로 `nullptr`이 되지는 않는다.

### Q11. 이름 있는 `T&&` 매개변수의 값 범주는?

**학습자 답변**

식별 가능한 이름을 가지므로 lvalue라고 정확히 답했다.

**평가: 🟢**

선언된 참조 타입과 이름을 사용한 표현식의 값 범주는 별개다. 다시 이동 대상으로 전달하려면 `std::move`가 필요하다.

### Q12. 값 범주를 분류하면?

```cpp
a;                  // lvalue
std::move(a);       // xvalue
Buffer(200);        // prvalue
a = Buffer(300);    // lvalue
```

**학습자 답변**

네 표현식을 모두 정확히 분류했다.

**평가: 🟢**

대입 연산자는 일반적으로 `T&`를 반환하므로 전체 대입 표현식은 lvalue다.

### Q13. `const` 객체에 `std::move`를 적용하면?

**학습자 답변**

복사 생성자가 호출된다는 결론은 맞았으나, xvalue가 lvalue와 rvalue 양쪽의 가능태라고 설명했다.

**평가: 🟡**

`std::move(constObject)`는 `const T&&`인 xvalue다. `const T&&`는 원본을 수정할 수 있는 `T&&`에 바인딩할 수 없지만 `const T&`에는 바인딩할 수 있으므로 보통 복사가 선택된다.

```text
glvalue = lvalue + xvalue
rvalue  = xvalue + prvalue
```

### Q14. 지역 객체의 값 반환과 우측값 참조 반환은?

**학습자 답변**

prvalue 반환과 이름 있는 지역 객체의 값 반환은 안전하고, 지역 객체를 `T&&`로 반환하는 것은 수명 종료 때문에 위험하다고 답했다.

**평가: 🟢 / 용어 보완**

값 반환에는 복사 생략, NRVO 또는 암시적 이동이 적용될 수 있다. `T&&`로 지역 객체를 반환하면 댕글링 포인터가 아니라 **댕글링 참조**가 된다.

### Q15. 사용자 선언 소멸자가 암시적 이동에 미치는 영향은?

**학습자 답변**

사용자 선언 소멸자가 암시적 이동 생성을 억제하고, `unique_ptr`은 복사할 수 없어 컴파일 오류가 발생한다고 정확히 답했다.

**평가: 🟢**

이동 전용 클래스로 만들려면 복사는 `= delete`, 이동은 `noexcept = default`로 명시할 수 있다.

### Q16. Rule of Zero란?

**학습자 답변**

원시 포인터를 소유한 클래스는 복사와 해제를 직접 처리해야 하지만, `vector` 같은 RAII 타입을 사용한 클래스는 특별 멤버 함수 없이 자원 관리를 해결할 수 있다고 설명했다.

**평가: 🟢**

Rule of Zero는 자원 관리를 RAII 멤버 타입에 맡겨 클래스가 다섯 특별 멤버 함수를 직접 작성하지 않도록 설계하는 원칙이다.

### Q17. 헤더의 전역 `static`과 클래스 정적 멤버는 각각 몇 개인가?

**학습자 답변**

헤더의 `static int globalCount`는 헤더를 포함한 세 번역 단위에 각각 하나씩 존재하고, `Counter::objectCount`는 프로그램 전체에 하나 존재한다고 답했다.

**평가: 🟢**

전역 `static`은 내부 연결을 가져 번역 단위마다 독립적이다. 정적 데이터 멤버는 객체 내부에 들어 있지 않으며, 클래스 밖의 유일한 정의가 프로그램 전체의 저장 공간 하나를 만든다.

## 보완 항목

### 1. `std::lock_guard` 이름

- 원리: 정확히 설명함.
- 보완: 상호 배제 잠금을 기본 RAII로 관리하는 타입 이름을 즉시 인출할 것.

### 2. 깊은 복사 코드의 단위와 문법

- `const T&`로 원본을 받는다.
- 배열은 `new int[count]`처럼 타입을 명시한다.
- `memcpy`에는 원소 수가 아니라 `sizeof(T) * count` 바이트를 전달한다.

### 3. `const`와 값 범주

- `std::move`는 `const`를 제거하지 않는다.
- xvalue는 lvalue와 rvalue의 중간 상태가 아니라 glvalue와 rvalue의 교집합이다.

### 4. 댕글링 포인터와 댕글링 참조

- 포인터를 반환한 것이 아니라 `T&&`를 반환했다면 댕글링 참조라고 표현한다.
