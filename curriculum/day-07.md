## 질답 기록

### Q1. 비가상 함수를 기반 포인터로 호출하면?

```cpp
Player player;
Character* character = &player;

player.Attack();
character->Attack();
```

**학습자 답변**

두 호출 모두 `Player::Attack()`이라고 답했다.

**평가: 🟡**

`Attack()`이 가상 함수가 아니면 정적 타입을 기준으로 컴파일 시 호출을 결정한다. 첫 호출은 `Player::Attack()`, 둘째 호출은 `Character::Attack()`이다.

`Player::Attack()`과 `Character::Attack()`은 별개의 함수다. `player.Attack()`에서는 파생 클래스의 동일한 이름이 기반 클래스 함수를 숨기며, `player.Character::Attack()`처럼 명시하면 기반 구현을 호출할 수 있다.

### Q2. `virtual`이 추가하는 것은?

기반 클래스 함수가 `virtual`이면 기반 포인터나 참조로 호출해도 실제 객체의 동적 타입에 맞는 최종 재정의 함수를 실행한다. 두 함수를 하나로 합치는 것이 아니라 재정의 관계에 동적 디스패치를 적용한다.

### Q3. `override`의 역할은?

**학습자 답변**

`override`를 생략해도 재정의가 처리되며, 해당 함수가 재정의 함수임을 명시한다고 답했다.

**평가: 🟢**

`override`는 동적 다형성을 새로 만드는 키워드가 아니다. 기반 가상 함수를 정확히 재정의하는지 컴파일러가 검사하도록 한다. `const`, 매개변수 타입 등이 다르면 컴파일 오류로 실수를 발견할 수 있다.

### Q4. 기반 함수와 파생 함수의 `const`가 다르면?

```cpp
virtual void Attack() const; // Character
void Attack();               // Player
```

**학습자 답변**

`Player::Attack()`이 호출될 것으로 예상했다.

**평가: 🟡**

두 함수는 시그니처가 달라 재정의 관계가 아니다. `player.Attack()`은 `Player::Attack()`을 호출하지만, `Character*`를 통한 가상 호출에는 파생 최종 재정의가 없으므로 `Character::Attack() const`가 호출된다.

### Q5. 다형적 기반 클래스에 가상 소멸자가 필요한 이유는?

**학습자 답변**

가상 소멸자가 없으면 기반 포인터 삭제에서 파생 소멸자가 호출되지 않으며, `virtual ~Character()`로 실제 객체에 맞는 소멸자를 호출해야 한다고 답했다.

**평가: 🟢**

가상 소멸자가 없는 기반 포인터로 파생 객체를 삭제하는 행위는 정의되지 않은 동작이다. 가상 소멸자가 있으면 `Player::~Player()` 이후 `Character::~Character()` 순으로 호출된다.

### Q6. 객체 슬라이싱이란?

```cpp
Player player;
Character character = player;
character.Print();
```

**학습자 답변**

일반 객체의 크기가 `Character`만큼이어서 `Character::Print()`가 호출되는지 추론했다.

**평가: 🟡 → 🟢**

값 복사 과정에서 `Player`의 기반 클래스 부분만 복사해 별도의 `Character` 객체를 만들고, 파생 클래스 부분은 제거된다. 저장 위치가 스택인지 힙인지는 핵심이 아니다. 새 객체의 동적 타입 자체가 `Character`이므로 가상 함수도 기반 구현을 호출한다.

### Q7. 참조는 왜 슬라이싱되지 않는가?

```cpp
Character& character = player;
character.Print();
```

**학습자 답변**

참조는 실제 객체를 가리키므로 `Player::Print()`가 호출된다고 답했다.

**평가: 🟢**

참조는 새 기반 객체를 복사하지 않고 기존 `Player`의 별칭이 된다. 포인터도 같은 이유로 슬라이싱되지 않는다.

### Q8. 순수 가상 함수와 추상 클래스란?

```cpp
virtual void Update() = 0;
```

**학습자 답변**

파생 클래스가 구현해야 하는 순수 가상 함수이며, 이를 가진 클래스는 직접 객체화할 수 없지만 기반 포인터로 파생 객체를 업캐스팅해 사용할 수 있다고 답했다.

**평가: 🟢**

순수 가상 함수도 별도의 정의를 가질 수 있다. 다만 순수 가상 함수가 남아 있는 클래스는 추상 클래스이므로 직접 인스턴스화할 수 없다.

### Q9. 생성자 안에서 가상 함수를 호출하면?

**학습자 답변**

실제 생성 대상이 `Player`이므로 기반 생성자에서도 `Player::Print()`가 호출될 것으로 예상했다.

**평가: 🟡**

기반 생성자가 실행되는 동안 파생 부분은 아직 생성되지 않았다. 따라서 기반 생성자 안의 가상 호출은 현재 생성 중인 기반 클래스 구현을 호출한다. 파생 생성자가 이후 실행된다.

```text
Character Print
Player Constructor
```

### Q10. 소멸자 안에서 가상 함수를 호출하면?

**학습자 답변**

파생 소멸자에서는 `Player::Print()`, 파생 부분이 사라진 뒤 실행되는 기반 소멸자에서는 `Character::Print()`가 호출된다고 정확히 설명했다.

**평가: 🟢**

```text
Player Print
Player-
Character Print
Character-
```

### Q11. `std::vector<Character>`에서 다형성이 유지되는가?

**학습자 답변**

가상 함수가 있으므로 작동할 것으로 예상했다.

**평가: 🔴 → 🟢**

```cpp
std::vector<Character> characters;
characters.push_back(Player{});
```

저장 시점에 `Player`가 `Character` 값으로 복사되어 슬라이싱된다. 반복문에서 참조를 사용해도 이미 파생 부분이 사라졌으므로 복구되지 않는다.

다형적 객체를 컨테이너가 소유한다면 다음처럼 저장할 수 있다.

```cpp
std::vector<std::unique_ptr<Character>> characters;
characters.push_back(std::make_unique<Player>());
characters.push_back(std::make_unique<Monster>());
```

실제 파생 객체는 온전하게 존재하고 컨테이너에는 소유 포인터가 저장된다. 기반 클래스에는 가상 소멸자가 필요하다.

### Q12. 값 매개변수와 참조 매개변수의 차이는?

**학습자 답변**

값 전달에서는 `Character::Print()`, 참조 전달에서는 `Player::Print()`가 호출되며 그 차이는 슬라이싱이라고 답했다.

**평가: 🟢**

`const Character&`에서 호출하려면 `Print()` 역시 `const` 멤버 함수여야 한다는 조건을 추가로 확인했다.

### Q13. 안전한 다운캐스팅은?

**학습자 답변**

`dynamic_cast<Player>`를 사용하면 된다고 답했다.

**평가: 🟡**

포인터 변환의 정확한 문법은 다음과 같다.

```cpp
if (Player* player = dynamic_cast<Player*>(character))
{
    player->UseSkill();
}
```

실패하면 `nullptr`을 반환한다. 참조 캐스팅 실패는 `std::bad_cast`를 던진다. 런타임 다운캐스팅에는 기반 타입이 하나 이상의 가상 함수를 가진 다형적 타입이어야 한다.

### Q14. 업캐스팅과 다운캐스팅의 차이는?

**학습자 답변**

`Player*`에서 `Character*`는 업캐스팅이고, 반대는 다운캐스팅이며 기반 포인터만으로 실제 객체가 `Player`인지 알 수 없으므로 암시적 다운캐스팅은 허용되지 않는다고 답했다.

**평가: 🟢**

### Q15. `final`은 무엇을 금지하는가?

**학습자 답변**

처음 접한 개념이라 설명을 요청했다. 설명 후 `Player::Attack() final`을 `Warrior`에서 재정의하면 컴파일 오류라는 점을 정확히 답했다.

**평가: 🔴 → 🟢**

- 클래스 뒤의 `final`: 추가 상속 금지
- 가상 함수 뒤의 `final`: 추가 재정의 금지
- `override`: 올바른 재정의인지 검사

## 오답 및 보완 항목

### 1. 비가상 함수 호출

- 오답: 기반 포인터가 `Player`를 가리키면 비가상 함수도 파생 구현을 호출한다고 판단함.
- 교정: 비가상 함수는 호출 표현식의 정적 타입을 기준으로 컴파일 시 결정한다.

### 2. 재정의 시그니처

- 오답 경향: 이름이 같으면 가상 함수가 연결된다고 판단함.
- 교정: 매개변수와 `const` 등을 포함한 재정의 조건이 일치해야 동적 디스패치 대상이 된다.

### 3. 객체 슬라이싱의 기준

- 오답 경향: 스택에 할당되거나 변수의 메모리 크기가 한정되어 발생한다고 설명함.
- 교정: 저장 위치와 무관하게 파생 객체를 기반 객체에 **값으로 복사**할 때 기반 부분만 남는 현상이다.

### 4. 생성·소멸 중 가상 호출

- 오답: 기반 생성자에서도 최종 파생 구현이 호출된다고 판단함.
- 교정: 아직 생성되지 않았거나 이미 소멸한 파생 부분으로는 디스패치하지 않는다.

### 5. 값 기반 다형적 컨테이너

- 오답: `vector<Character>`에서도 가상 함수가 다형성을 유지한다고 판단함.
- 교정: 저장 시 이미 슬라이싱된다. 소유권이 필요한 다형적 컨테이너는 `vector<unique_ptr<Character>>` 등을 사용한다.

### 6. `dynamic_cast` 문법

- 보완: 포인터를 다운캐스팅할 때는 `dynamic_cast<Player*>(character)`처럼 대상 포인터 타입을 명시하고 `nullptr`을 검사한다.

## 최종 30초 답변

> C++의 동적 다형성은 기반 클래스의 가상 함수를 파생 클래스가 재정의하고, 실제 파생 객체를 기반 클래스 포인터나 참조로 호출할 때 작동합니다. `override`는 필수 키워드는 아니지만 정확한 재정의 여부를 컴파일러가 검사하게 합니다. 반면 파생 객체를 기반 객체에 값으로 복사하면 파생 부분이 제거되는 객체 슬라이싱이 발생하여 동적 타입을 잃습니다. 따라서 다형적 객체는 포인터나 참조로 다루고, 기반 포인터로 삭제할 수 있도록 기반 클래스 소멸자를 `virtual`로 선언해야 합니다.
