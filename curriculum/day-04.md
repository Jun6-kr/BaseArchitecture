### Q1. 기반 클래스·멤버·파생 클래스의 생성·소멸 순서는?

**학습자 답변 요약**

생성 순서는 기반 클래스 → 멤버 → 파생 클래스 생성자 본문으로 정확히 답했지만, 소멸에서는 멤버를 파생 클래스 소멸자 본문보다 먼저 배치했다.

**평가: 🟡**

정확한 순서는 다음과 같다.

```text
생성: 기반 클래스 → 멤버 선언 순서 → 파생 클래스 생성자 본문
소멸: 파생 클래스 소멸자 본문 → 멤버 역순 → 기반 클래스
```

### Q3. 수동 `lock/unlock`에서 조기 반환이 발생하면?

**학습자 답변 요약**

잠금이 풀리지 않아 이후 같은 스레드의 재잠금이나 다른 스레드의 접근이 막힐 수 있다고 답했다. RAII 잠금 타입의 이름은 기억하지 못했고, 멤버 뮤텍스에 지역 RAII 객체가 어떻게 적용되는지 질문했다.

**평가: 🟡 → 🟢**

## 질답 기록

### Q1. 원시 포인터 멤버를 기본 복사하면?

```cpp
Buffer a;
Buffer b = a;
```

**학습자 답변 변화**

처음에는 `b`의 기본 생성자가 별도 배열을 할당한다고 예상했다. 질문을 따라가며 `Buffer b = a;`는 기본 생성 후 대입이 아니라 복사 생성이고, 기본 복사는 `b.data = a.data`처럼 주소만 복사할 것이라고 스스로 교정했다.

**평가: 🔴 → 🟢**

컴파일러가 생성한 복사 생성자는 포인터가 가리키는 배열이 아니라 포인터 주소를 멤버별 복사한다. 두 객체가 하나의 배열을 가리키게 되며, 소멸 시 댕글링 포인터와 이중 해제가 발생한다. 이것이 얕은 복사다.

### Q2. 복사 생성과 복사 대입의 차이는?

**학습자 답변**

`Buffer b = a;`는 복사 생성자를 호출하고, 이미 존재하는 `c`에 `c = a;`를 수행하면 `operator=(const Buffer&)`가 호출된다고 답했다.

**평가: 🟢**

복사 생성은 자원이 없는 새 객체를 만들고, 복사 대입은 이미 자원을 가지고 있을 수 있는 객체의 상태를 교체한다.

### Q3. 깊은 복사 생성자를 구현하면?

**학습자 답변**

```cpp
Buffer(const Buffer& other)
    : data(new int[100])
{
    memcpy(data, other.data, sizeof(int) * 100);
}
```

**평가: 🟢**

`int`는 단순 복사가 가능한 타입이므로 올바르다. 일반적인 C++ 코드에서는 원소의 복사 동작을 사용하도록 `std::copy`를 선택할 수 있다.

### Q4. 고정 크기 버퍼의 복사 대입에서도 새 배열이 필요한가?

**학습자 답변 요약**

모든 객체가 항상 100칸을 이미 할당했다면 기존 공간에 바로 복사할 수 있는데 왜 다시 할당해야 하는지 질문하고, `memcpy`만으로 구현할 수 있다고 제안했다.

**평가: 🟢**

예제 조건을 정확히 짚었다. 고정 크기와 항상 유효한 저장 공간이 클래스 불변식이라면 자기 대입을 확인한 뒤 기존 배열에 복사하면 충분하다. 객체마다 크기가 다른 경우에 새 공간이 필요하다.

### Q5. 가변 크기 버퍼의 복사 대입을 구현하면?

**학습자 답변 요약**

값 비교로 자기 대입을 확인하고, 새 배열을 할당한 뒤 포인터가 유효하면 기존 배열을 해제해 교체하는 코드를 작성했다.

**평가: 🟡**

자기 대입은 `this == &other`로 객체 정체성을 비교해야 한다. 일반 `new`는 실패 시 `nullptr`이 아니라 예외를 던진다. 새 배열에 데이터를 복사하고 `size`도 갱신해야 한다.

```cpp
Buffer& operator=(const Buffer& other)
{
    if (this == &other)
        return *this;

    int* newData = new int[other.size];
    std::copy(other.data, other.data + other.size, newData);

    delete[] data;
    data = newData;
    size = other.size;
    return *this;
}
```

새 자원 준비가 성공한 뒤 기존 자원을 해제하면 할당 실패 시 기존 객체 상태를 유지할 수 있다.

### Q6. 이동 생성자는 무엇을 하는가?

**학습자 답변 요약**

우측 참조와 `std::move`를 이용해 새 메모리를 만들지 않고 기존 메모리의 소유권을 다른 객체에 넘기며, 할당을 생략해 빠르다고 설명했다.

**평가: 🟢 / 표현 보완**

정확한 용어는 우측값 참조다. `std::move` 자체는 자원을 이동하지 않고 이동 가능한 값으로 취급하도록 캐스팅한다. 실제 포인터 인계와 원본 초기화는 이동 생성자가 수행한다. 이동은 할당뿐 아니라 원소 복사도 생략할 수 있다.

### Q7. 이동된 객체는 어떻게 되는가?

**학습자 답변 요약**

직접 작성한 이동 생성자에 따라 원본은 `size == 0`, `data == nullptr`가 되고 대상은 기존 배열을 소유한다고 답했다. 원본에 새 자원을 할당하기 전 기존 포인터를 사용하는 것은 위험하다고 설명했다.

**평가: 🟢**

일반적으로 이동된 객체는 유효하지만 값은 특정할 수 없는 상태다. 안전하게 소멸하거나 새 값을 대입할 수 있으며, 타입이 보장하지 않는 이동 전 상태를 가정해서는 안 된다. 현재 구현은 명시적으로 빈 상태를 보장한다.

### Q8. 이동 대입 연산자를 구현하면?

**학습자 답변 요약**

자기 이동 대입을 방어하고 기존 배열을 해제한 뒤 `std::move(other.data)`로 포인터를 받고, `sizeof(data)`로 크기를 저장한 다음 원본을 비웠다.

**평가: 🟡**

원시 포인터에 `std::move`를 사용해도 주소 복사와 같으므로 `data = other.data`가 명확하다. `sizeof(data)`는 배열 길이가 아니라 포인터 크기이므로 `size = other.size`를 사용해야 한다.

```cpp
Buffer& operator=(Buffer&& other) noexcept
{
    if (this == &other)
        return *this;

    delete[] data;
    size = other.size;
    data = other.data;

    other.size = 0;
    other.data = nullptr;
    return *this;
}
```

### Q9. Rule of Five의 다섯 함수는?

**학습자 답변 요약**

복사 생성자, 복사 대입 연산자, 이동 생성자, 이동 대입 연산자를 설명했으나 다섯 번째를 기억하지 못했다.

**평가: 🟡**

다섯 번째는 소멸자다. 직접 자원을 관리하는 클래스는 소멸, 복사, 이동의 소유권 정책을 함께 검토해야 한다.

### Q10. `vector`와 `unique_ptr` 중 복사 가능한 Rule of Zero 버퍼에는 무엇이 적합한가?

**학습자 답변**

`unique_ptr`은 복사할 수 없으므로 `vector`가 적합하다고 답했다.

**평가: 🟢**

`vector`는 소멸·깊은 복사·효율적인 이동을 이미 구현했으므로 바깥 클래스가 특별 멤버 함수를 직접 작성하지 않아도 된다. 단독 소유의 이동 전용 클래스라면 `unique_ptr`도 Rule of Zero에 적합하다.

### Q11. `unique_ptr` 멤버를 가진 클래스의 암시적 복사와 이동은?

**학습자 답변 요약**

복사는 소유권을 나눌 수 없어 컴파일되지 않고, 이동은 기존 소유권을 대상 객체로 이관하므로 가능하다고 답했다.

**평가: 🟢**

`unique_ptr`의 삭제된 복사 생성자 때문에 바깥 클래스의 암시적 복사도 삭제된다. 특별 멤버를 직접 선언하지 않았다면 `unique_ptr`의 이동을 사용하는 바깥 클래스의 암시적 이동은 가능하다.

### Q12. 빈 소멸자를 직접 선언하면 암시적 이동은 유지되는가?

**학습자 답변**

소멸자가 이동 생성자에 영향을 주는지 알지 못했다.

**평가: 🔴**

사용자 선언 소멸자가 있으면 컴파일러는 이동 생성자와 이동 대입 연산자를 암시적으로 생성하지 않는다. `unique_ptr` 때문에 복사도 삭제된 클래스라면 `std::move`를 사용해도 컴파일되지 않는다. 이동을 유지하려면 명시적으로 `= default`할 수 있다.

### Q13. Rule of Three, Five, Zero의 의미는?

**학습자 답변 변화**

Rule of Five의 구성은 기억했지만 왜 세 함수와 다섯 함수가 묶이는지는 알지 못했다. 설명 후 원시 포인터를 직접 소유하면 메모리 누수·댕글링 포인터 등의 오류를 막기 위해 Rule of Five를 검토해야 하고, `vector`는 바깥 객체 수명에 맞춰 자원을 스스로 관리하므로 Rule of Zero가 가능하다고 정리했다.

**평가: 🟡 → 🟢**

이 규칙들은 문법적 강제가 아니라 자원 소유권을 일관되게 설계하기 위한 지침이다.

## 오늘 잘한 점

- `Buffer b = a`가 기본 생성 후 대입이 아니라 복사 생성이라는 사실을 설명 후 정확히 구분했다.
- 깊은 복사 생성자를 직접 구현했다.
- 고정 크기 버퍼에서 불필요한 재할당 조건을 발견하고 예제의 전제를 비판적으로 검토했다.
- 복사와 이동의 소유권 차이를 이해하고 `unique_ptr`의 복사 불가·이동 가능 특성을 정확히 적용했다.
- 이동 대입에서 기존 자원을 먼저 정리하고 원본을 빈 상태로 만드는 전체 구조를 이해했다.
- 원시 자원 소유 클래스와 RAII 멤버 클래스가 각각 Rule of Five와 Rule of Zero에 연결되는 이유를 최종적으로 설명했다.

## 오답 및 보완 항목

### 1. 복사 초기화와 기본 생성의 혼동

- 오답: `Buffer b = a`에서 `b`의 기본 생성자가 먼저 배열을 할당한다고 예상함.
- 교정: 새 객체가 기존 객체로 초기화되므로 복사 생성자가 호출된다.

### 2. 복사 대입의 자기 대입과 예외 안전성

- 오답: `other == *this`로 자기 대입을 확인하고 `new`가 `nullptr`을 반환하는지 검사함.
- 교정: 정체성은 `this == &other`로 비교한다. 일반 `new`는 실패 시 예외를 던지므로 새 자원을 먼저 준비한 후 기존 자원을 교체한다.

### 3. `std::move`의 역할

- 보완: `std::move`가 직접 메모리를 이동하는 것이 아니라 이동 연산을 선택할 수 있도록 우측값으로 변환한다.

### 4. `sizeof(pointer)`와 배열 길이

- 오답: 이동 대입에서 `sizeof(data)`로 배열의 크기를 저장함.
- 교정: `sizeof(data)`는 포인터 자체의 바이트 크기다. 논리적 배열 길이는 별도 `size` 멤버로 전달해야 한다.

### 5. Rule of Five의 소멸자

- 오답: 복사·이동 함수 네 개는 기억했지만 소멸자를 빠뜨림.
- 교정: 직접 소유한 자원의 해제 정책이 복사·이동 정책과 함께 다섯 함수로 묶인다.

### 6. 사용자 선언 소멸자와 암시적 이동

- 오답: 빈 소멸자가 이동 생성자 생성에 영향을 주는지 알지 못함.
- 교정: 사용자 선언 소멸자는 암시적 이동 생성자와 이동 대입 연산자의 생성을 억제한다. 필요하면 이동 함수를 명시적으로 `= default`한다.

## 최종 30초 답변

> 원시 자원을 직접 소유하는 클래스에서 소멸자, 복사 생성자, 복사 대입 연산자 중 하나가 필요하다면 나머지도 함께 검토해야 한다는 지침이 Rule of Three입니다. C++11 이후에는 이동 생성자와 이동 대입 연산자를 더한 Rule of Five로 확장됩니다. 현대 C++에서는 `vector`, `string`, 스마트 포인터 같은 RAII 타입에 자원 관리를 맡겨 특별 멤버 함수를 직접 작성하지 않는 Rule of Zero를 우선합니다. 이렇게 하면 누수, 얕은 복사, 이중 해제, 예외 안전성 문제를 이미 검증된 타입에 맡길 수 있습니다.
