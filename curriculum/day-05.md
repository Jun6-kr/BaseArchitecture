## 이전 학습 복습

### Q1. 사용자 선언 소멸자가 있는 `unique_ptr` 소유 클래스는 암시적으로 이동되는가?

**학습자 답변 요약**

컴파일은 될 것이라고 답하면서도, 사용자 선언 소멸자가 암시적 이동 생성자를 억제하므로 직접 이동 생성자가 필요하다고 설명했다. 복사 생성자와 복사 대입 연산자를 삭제해야 한다고 답했다.

**평가: 🟡**

두 설명은 서로 충돌한다. 사용자 선언 소멸자 때문에 암시적 이동이 생성되지 않고, `unique_ptr` 멤버 때문에 암시적 복사도 삭제되므로 `Buffer b = std::move(a);`는 컴파일되지 않는다. 이동 전용 타입으로 만들려면 복사는 `= delete`, 이동 생성자와 이동 대입 연산자는 `= default`로 명시한다.

## 질답 기록

### Q1. `std::move`가 실제 포인터를 옮기고 원본을 비우는가?

**학습자 답변 변화**

처음에는 `std::move`가 원본의 자원을 대상에 넘기고 원본을 `nullptr`로 만드는지 확신하지 못했다. 실제 이동을 누가 수행하는지 질문했다.

**평가: 🟡 → 🟢**

`std::move`는 실제 자원을 이동하지 않는다. 개념적으로 `static_cast<T&&>`와 같은 변환을 수행해 표현식을 xvalue로 만들고, 이동 생성자나 이동 대입 연산자가 선택될 기회를 제공한다. 실제 자원 이전과 원본 상태 변경은 선택된 이동 연산 또는 멤버 타입의 이동 연산이 수행한다.

원시 포인터의 기본 이동은 주소만 복사하고 원본을 비우지 않으므로 직접 관리가 필요하다. `unique_ptr`은 자신의 이동 연산에서 소유권을 넘기고 원본을 빈 상태로 만든다.

### Q2. lvalue와 rvalue 오버로드 중 무엇이 선택되는가?

```cpp
Use(a);
Use(std::move(a));
Use(Buffer(200));
```

**학습자 답변 요약**

각각 lvalue, rvalue, rvalue 오버로드가 선택된다고 정확히 답했다. `a`는 메모리에 올라간 객체이고, `std::move`는 rvalue로 만들며, 생성자는 rvalue를 반환한다고 설명했다.

**평가: 🟢 / 설명은 🟡**

메모리 존재 여부는 lvalue의 기준이 아니다. `a`는 이름으로 정체성을 반복해서 식별할 수 있는 lvalue 표현식이다. `std::move(a)`는 xvalue, `Buffer(200)`은 임시 객체를 만드는 prvalue다. 생성자는 값을 반환하지 않는다.

### Q3. lvalue, xvalue, prvalue를 분류하면?

```cpp
a;                  // lvalue
std::move(a);       // xvalue
Buffer(200);        // prvalue
a = Buffer(300);    // lvalue
```

**학습자 답변 요약**

앞의 세 표현식은 정확히 분류했으나 대입 표현식 전체는 prvalue로 추측했다. 대입 연산자가 참조를 반환했던 사실을 떠올렸다.

**평가: 🟡**

대입 연산자는 일반적으로 `T&`를 반환하므로 대입 표현식 전체는 lvalue다. 함수 호출 결과는 반환형이 `T`면 prvalue, `T&`면 lvalue, `T&&`면 xvalue다.

### Q4. 값 범주의 전체 관계는?

```text
value category
├─ glvalue
│  ├─ lvalue
│  └─ xvalue ─┐
└─ prvalue ───┴─ rvalue
```

**교정 내용**

xvalue는 lvalue와 rvalue 양쪽에 속하는 범주가 아니다. xvalue는 객체의 정체성을 나타내는 glvalue이면서, 자원을 재사용할 수 있는 rvalue다. `rvalue = xvalue + prvalue`, `glvalue = lvalue + xvalue`다.

### Q5. 이름 있는 우측값 참조 매개변수는 함수 안에서 어떤 값 범주인가?

```cpp
void Forward(Buffer&& value)
{
    Use(value);
    Use(std::move(value));
}
```

**학습자 답변 요약**

직감적으로 첫 호출은 lvalue, 두 번째는 rvalue 오버로드라고 맞혔지만 이유는 설명하지 못했다.

**평가: 🟡 → 🟢**

`value`의 선언 타입은 `Buffer&&`지만, 이름 있는 변수 표현식 `value`는 lvalue다. 다시 이동 대상으로 전달하려면 `std::move(value)`로 xvalue를 만들어야 한다. 선언된 참조 타입과 표현식의 값 범주는 별개다.

### Q6. 이동 생성자 안에서 멤버를 그대로 사용하면 복사되는가?

```cpp
Player(Player&& other)
    : name(other.name)
{
}
```

**학습자 답변 요약**

`other.name`은 복사되고, `name(std::move(other.name))`으로 수정해야 이동된다고 답했다. 원본 문자열을 직접 빈 문자열로 만들면 된다고 제안했다.

**평가: 🟢 / 원본 처리 보완**

`other.name`은 이름을 통해 접근한 lvalue이므로 복사된다. `std::move`를 적용해야 문자열의 이동 생성자를 선택할 수 있다. 이동된 `std::string`은 유효하지만 값이 특정되지 않는 상태이며 반드시 빈 문자열이라고 보장되지 않는다. 직접 빈 문자열을 대입할 필요도 없다.

### Q7. `const` 객체에 `std::move`를 적용하면?

```cpp
const Buffer a(100);
Buffer b = std::move(a);
```

**학습자 답변 변화**

처음에는 `std::move`가 `Buffer&&`를 반환할 것이라고 생각했다. 질문의 의도를 따라 `const Buffer&&`와 복사 생성자 호출을 추측했으며, 이후 입력의 `const`를 놓쳤다고 정정했다.

**평가: 🟡 → 🟢**

`std::move`는 `const`를 제거하지 않는다. 수정 가능한 `Buffer`에 적용하면 `Buffer&&`, `const Buffer`에 적용하면 `const Buffer&&`가 된다. 일반적인 이동은 원본을 빈 상태로 변경해야 하므로 `Buffer&&`를 받으며, `const Buffer&&`는 받을 수 없다. 대신 `const Buffer&` 복사 생성자가 선택된다.

### Q8. 지역 객체의 값 반환에 `std::move`를 붙여야 하는가?

```cpp
Buffer MakeBuffer()
{
    Buffer result(100);
    return result;
}
```

**학습자 답변 요약**

처음에는 `std::move`로 메모리를 이관하는 편이 좋다고 생각했으나, 값 반환 과정에서 다시 객체 타입으로 변환되므로 의미 없는 작업일 수 있다고 추론했다.

**평가: 🟡 → 🟢**

`return result;`은 가능하면 NRVO로 호출자의 결과 저장 공간에 직접 객체를 생성한다. NRVO가 적용되지 않아도 지역 반환 객체에 대한 암시적 이동이 가능하다. `return std::move(result);`은 반환식이 지역 변수 이름 자체가 아니게 되어 NRVO 적용을 방해하고 불필요한 이동 생성을 추가할 수 있다.

### Q9. prvalue 반환, 이름 있는 지역 객체 반환, `T&&` 지역 참조 반환의 차이는?

```cpp
Buffer MakeA()  { return Buffer(100); }
Buffer MakeB()  { Buffer result(100); return result; }
Buffer&& MakeC(){ Buffer result(100); return std::move(result); }
```

**학습자 답변 요약**

A가 가장 안전하며 복사 생략이 된다고 답했다. B도 함수 종료 시 지역 객체가 소멸하므로 위험할 수 있다고 생각했고, C는 댕글링 참조가 발생할 것이라고 추측했다.

**평가: 🟡**

A와 B는 모두 안전한 값 반환이다. A는 C++17 이후 반환 결과를 직접 생성하는 복사 생략 대상이다. B는 NRVO가 가능하고, 적용되지 않으면 함수가 끝나기 전에 별도 반환 객체를 이동 생성한다. C는 새로운 객체를 만들지 않고 지역 객체를 가리키는 참조만 반환하므로 함수 종료 후 댕글링 참조가 된다.

### Q10. `std::move`를 면접 답변으로 설명하면?

**학습자 답변 요약**

기존 객체를 우측값 참조로 반환하며 xvalue가 lvalue와 rvalue 양쪽에 속하는지 질문했다. 이름 있는 우측값 참조 매개변수는 lvalue로 취급되고, `const` 객체에서는 원본을 변경할 수 없으므로 이동에 적합하지 않다고 설명했다. 지역 객체 반환에서 `std::move`를 사용하면 함수 종료 후 반환 주소가 무효가 된다고 답했다.

**평가: 🟡**

`std::move`는 객체를 옮기거나 주소를 반환하는 함수가 아니라 xvalue로 변환하는 캐스트다. xvalue는 glvalue이자 rvalue지만 lvalue는 아니다. 값 반환의 `return std::move(local);`은 댕글링을 일으키지 않으며 NRVO를 방해할 수 있다는 것이 문제다. `T&&` 참조로 지역 객체를 반환할 때만 댕글링 참조가 발생한다.

## 오늘 잘한 점

- `a`, `std::move(a)`, 임시 객체의 오버로드 선택을 정확히 판단했다.
- 이름 있는 우측값 참조가 lvalue라는 문제를 직감적으로 맞혔고, 이동 생성자 멤버 초기화에 바로 적용했다.
- 입력 객체의 `const`를 확인한 뒤 `const T&&`와 복사 생성자 선택을 정확히 정리했다.
- 지역 객체의 값 반환과 우측값 참조 반환이 다르다는 점을 교정 후 이해했다.
- `std::move`가 원본을 직접 비우는지 의문을 제기해 실제 이동 주체를 분명히 구분했다.

## 오답 및 보완 항목

### 1. 암시적 이동 가능 여부

- 오답: 사용자 선언 소멸자가 이동 생성을 막는다고 알면서도 이동 코드가 컴파일된다고 답함.
- 교정: 이동과 복사 후보가 모두 사용 불가능하면 `std::move`를 사용해도 컴파일되지 않는다.

### 2. lvalue의 정의

- 오답 경향: 메모리에 존재하는 객체를 lvalue라고 설명함.
- 교정: 값 범주는 표현식의 성질이다. lvalue는 정체성을 지속적으로 식별할 수 있는 표현식이다.

### 3. xvalue의 위치

- 오답 경향: xvalue가 lvalue와 rvalue 양쪽에 속하는지 혼동함.
- 교정: xvalue는 glvalue와 rvalue의 교집합이며 lvalue는 아니다.

### 4. `std::move`와 실제 이동

- 오답 경향: `std::move`가 자원을 넘기고 원본을 비우는지 혼동함.
- 교정: `std::move`는 xvalue로 변환할 뿐이다. 실제 이동은 이동 생성자·이동 대입 연산자 또는 멤버의 이동 연산이 수행한다.

### 5. `const`와 이동

- 보완: `std::move`는 `const`를 제거하지 않는다. `const T&&`는 일반적인 `T&&` 이동 연산에 전달할 수 없어 복사가 선택될 수 있다.

### 6. 값 반환과 참조 반환

- 오답: 값으로 반환하는 이름 있는 지역 객체도 함수 종료 후 사라져 위험하다고 생각함.
- 교정: 값 반환은 호출자가 소유할 결과 객체를 NRVO 또는 이동으로 만든다. `T&&`로 지역 객체의 참조를 반환할 때만 댕글링 참조가 된다.

### 7. 지역 반환값의 `std::move`

- 오답: 값 반환에서도 지역 메모리 주소가 무효가 되어 댕글링이 발생한다고 설명함.
- 교정: 값 반환은 안전하지만 `std::move`가 NRVO를 방해해 불필요한 이동을 추가할 수 있다.

## 최종 30초 답변

> `std::move`는 실제 자원을 이동시키는 함수가 아니라 표현식을 xvalue로 변환해 이동 생성자나 이동 대입 연산자가 선택될 수 있게 하는 캐스트입니다. 실제 자원 이전은 선택된 이동 연산이 수행합니다. 우측값 참조 타입의 매개변수도 이름으로 사용하면 lvalue이므로 다시 이동하려면 `std::move`가 필요합니다. `const` 객체에 적용하면 `const T&&`가 되어 일반적인 이동 대신 복사가 선택될 수 있습니다. 지역 객체를 값으로 반환할 때는 `return result;`만으로 NRVO 또는 암시적 이동이 가능하므로 `std::move`를 붙이지 않습니다.
